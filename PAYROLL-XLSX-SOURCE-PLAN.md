# План подключения источника ФОТ из локального XLSX

## Подготовка

- Рабочая ветка: `feat/payroll-xlsx-source`.
- Папка источника переименована из ошибочного `xslx` в `xlsx`.
- Текущий файл источника: `xlsx/_03_Начисления_ЗП.xlsx`.
- Книгу с персональными данными нельзя коммитить или включать в Docker-образ.

## Изученная структура и контрольная логика

- В книге один лист `Untitled`, диапазон данных — `A1:AI25`.
- Колонки A–C: `ФИО`, `Должность`, `Направление`.
- Начиная с D каждый месяц занимает четыре колонки: оклад, отпускные, премия и бонус от продаж. Месяц и год указаны в первой строке, виды начислений — во второй.
- В текущем файле представлены январь–август 2026 года, формул нет.
- В книге 20 сотрудников; 14 из них относятся к пяти нужным направлениям: `Брендинг`, `Разработка сайтов`, `Видеоконтент`, `SMM`, `Рекламные кампании`.
- Направления `Управление`, `Продажи` и `Маркетинг` не импортируются.
- Строка 23 содержит `ИТОГО`, поэтому импорт должен исключать её явно, а также пропускать пустые строки и записи без полноценного ФИО.
- Контрольный результат за апрель 2026 года по пяти направлениям: 3 444 390 ₽. Для `Брендинга`: 557 800 ₽ оклада + 195 230 ₽ премии = 753 030 ₽.

## Импорт и хранение

- Добавить `exceljs` для чтения XLSX без изменения исходной книги.
- Распознавать русское название месяца и год из первой строки, проверять последовательность четырёх заголовков начислений и запрещать дубли периодов.
- Нормализовать пробелы и регистр названий направлений. Использовать справочное название `Разработка сайтов` во множественном числе.
- Пустое начисление считать нулём. Некорректное денежное значение в строке подходящего сотрудника считать ошибкой всего импорта; отрицательные значения сохранять как возможные корректировки.
- Хранить только агрегаты по источнику, году, месяцу и направлению — без ФИО и должностей. Оклад, отпускные, премию и бонус хранить отдельно как `Decimal(16,2)`; общий ФОТ вычислять их суммой.
- Добавить модели `PayrollMonthly` и `PayrollSyncState`, связать их с `DataSource` и `Direction`. Источник зарегистрировать с ключом `local-payroll-xlsx`, каждый запуск фиксировать через `SyncRun`.
- Нормализованные агрегаты сортировать и хешировать. При изменении одной транзакцией заменять текущие строки, обновлять статус и увеличивать ревизию. При ошибке оставлять предыдущие корректные данные в БД и сохранять русскоязычное описание ошибки.

## Настройки и мгновенное обновление

- В `.env.example` и локальном `.env` добавить настройки каталога и имени файла. Для текущего окружения использовать каталог `./xlsx` и файл `_03_Начисления_ЗП.xlsx`; путь не зашивать в TypeScript.
- Добавить папки `xlsx/` и `xslx/` в `.gitignore` и `.dockerignore`, чтобы файл не попал в Git или сборочный контекст.
- В Docker Compose монтировать каталог источника в контейнер `worker` только для чтения. Монтировать каталог, а не отдельный файл, чтобы корректно обрабатывать замену файла при сохранении Excel.
- При старте worker выполнить первичную синхронизацию, затем проверять файл через `fs.watchFile` с интервалом 500 мс. Перед чтением дождаться стабильных размера и времени изменения; временные ошибки блокировки Excel повторять в течение нескольких секунд.
- Не запускать два импорта одновременно: изменение во время активной синхронизации должно поставить один повторный запуск в очередь. При остановке worker снять наблюдение за файлом и корректно закрыть Prisma.
- Добавить `GET /api/sync/payroll` со статусом, ревизией, временем успешной синхронизации, количеством сотрудников и агрегатов, последним периодом и ошибкой.
- Добавить SSE `GET /api/updates/payroll?revision=N`, проверяющий ревизию раз в секунду. При новой ревизии клиент тихо перезапрашивает данные открытой вкладки без перезагрузки страницы и сброса фильтров.

## Проверка

- Unit-тесты парсера: двухстрочная шапка, месяцы и годы, четыре начисления, пустые значения, неизвестные направления, неполное ФИО, `ИТОГО`, пустые строки, дубли периодов и некорректные суммы.
- Тесты синхронизации: первая загрузка, неизменившийся хеш, атомарная замена, сохранение старых данных при ошибке, обновление ревизии и защита от параллельных запусков.
- Тесты дашборда: фильтры направлений, месяц/квартал/год, предыдущий период и правильное суммирование каждой составляющей ФОТ.
- E2E: новое название вкладки, KPI, линия графика, столбец таблицы, русские подсказки и обновление без сброса выбранного периода, направлений и группировки.
- Интеграционную проверку наблюдения выполнять на копии или сгенерированной тестовой книге; исходный файл не изменять. Обычное сохранение должно появляться на экране за 1–2 секунды.
- Финальные команды: `npm test`, `npm run lint`, `npm run build`, `docker compose config`, затем `docker compose up --build`.
- Исходный baseline уже проверен: 25 unit-тестов, lint и production build проходят.
