# Подключение дневного маркетингового факта через Apps Script

Инструкция для следующей сессии по подключению закрытой Google-таблицы с дневным маркетинговым фактом к Atlas.

## 1. Обязательное начало работы

До любых изменений проверить репозиторий:

```powershell
git status --short --branch
```

Затем создать отдельную ветку от актуальной `main`:

```powershell
git switch main
git pull --ff-only
git switch -c feature/marketing-actual-apps-script
```

Если в рабочем дереве появились чужие изменения, не удалять и не перезаписывать их. Ветку при сохранении этой инструкции пока не создавать.

## 2. Результат

- Закрытая таблица остаётся закрытой и сама отправляет данные через Apps Script.
- Факт хранится по дням, но дашборд группирует его по месяцам, кварталам и годам.
- Ручная правка появляется на экране через несколько секунд.
- Формулы, импорты, Sheets API и другие скрипты покрываются контрольной сверкой не позднее чем через минуту.
- Страница не перезагружается; вкладка, направления, период и группировка не сбрасываются.
- Очистка или удаление строки удаляет соответствующий факт.
- Синхронизация открытой таблицы плана продолжает работать.

## 3. Формат таблицы

Первая строка содержит:

1. `Дата`
2. `Направление`
3. `Посещения`
4. `Лиды`
5. `Рекламный бюджет, ₽`
6. `Конверсия Лид/Посещение`
7. `CPC, ₽`
8. `CPL, ₽`

Одна строка соответствует одному направлению за одну дату. Поддержать пять существующих направлений, 2026 год и не более 10 000 строк. Пустые строки игнорировать. Нули разрешить; отрицательные значения, дробные посещения/лиды, лиды больше посещений и дубликат `дата + направление` отклонять. Дату нормализовать в `YYYY-MM-DD` в часовом поясе таблицы.

## 4. Единый расчёт плана и факта

- бюджет = сумма бюджетов;
- посещения = сумма посещений;
- лиды = сумма лидов;
- конверсия = сумма лидов / сумма посещений;
- CPC = сумма бюджета / сумма посещений;
- CPL = сумма бюджета / сумма лидов.

При нулевом знаменателе возвращать `null`. Готовые конверсии, CPC и CPL не суммировать и не усреднять: поля таблицы использовать только для проверки строки. План и факт должны использовать общий серверный расчёт и одинаковое округление.

Дневной факт агрегировать в существующие месяцы, кварталы и год. Группировку «Дни» не добавлять. Накопленный факт текущего месяца сравнивать с полным месячным планом.

## 5. База данных

- Перевести `MarketingActual` с `year/month` на PostgreSQL `date`.
- Бюджет оставить Prisma `Decimal`.
- Добавить источник, лист, номер исходной строки и время изменения.
- Установить уникальность `дата + направление` и `источник + лист + номер строки`.
- Удалить миграцией только демонстрационный маркетинговый факт.
- Убрать факт из seed, чтобы контейнеры не перезаписывали реальные данные.
- Остальные демонстрационные разделы не менять.
- Расширить журнал типом webhook, внешним ID события и режимом синхронизации.
- Добавить сессии и части полного снимка, ревизию, время успешной синхронизации, число строк и максимальную дату.

Полный снимок применять одной транзакцией. При любой ошибке сохранять предыдущий успешный набор.

## 6. API и безопасность

Добавить:

```text
POST /api/integrations/google-sheets/marketing-actual
```

Контракт версии `1`:

- `patch` — затронутые или очищенные строки;
- `snapshot.offer` — хеш, число строк и частей;
- `snapshot.chunk` — часть максимум по 500 строк;
- `snapshot.commit` — проверка и атомарное применение.

Apps Script сначала читает таблицу одним пакетным вызовом и вычисляет SHA-256. При совпадении хеша полную загрузку пропустить. Иначе отправить части, проверить их комплектность, заголовки, строки, уникальность и итоговый хеш, затем заменить данные транзакцией.

Очищенная строка остаётся в `affectedRows`, но отсутствует в `rows`; сервер удаляет запись по исходному номеру строки. Операции защищать отдельным PostgreSQL advisory lock. Устаревший снимок не должен перезаписывать более свежий `patch`.

Подписывать запросы HMAC-SHA256 от:

```text
timestamp + "\n" + eventId + "\n" + rawBody
```

Заголовки:

```text
X-Atlas-Timestamp
X-Atlas-Event-Id
X-Atlas-Signature
```

На сервере использовать `timingSafeEqual`, окно времени пять минут, идемпотентность `eventId`, allowlist spreadsheet ID/листа и ограничения размера. Не логировать секрет, подпись и полный запрос. Ошибки должны быть по-русски.

Переменные окружения:

```text
MARKETING_ACTUAL_WEBHOOK_SECRET
MARKETING_ACTUAL_SPREADSHEET_ID
MARKETING_ACTUAL_SHEET_NAME
```

Реальные значения не коммитить; в `.env.example` оставить пустые примеры.

## 7. Apps Script и инструкция владельцу

Скрипт сохранить в `integrations/google-sheets/marketing-actual/Code.gs`. Он должен находить столбцы по заголовкам, передавать только разрешённые поля, нормализовать даты и поддерживать:

- устанавливаемый edit-trigger для немедленного `patch`;
- change-trigger для вставки, удаления и перестановки строк;
- минутный time-trigger для контрольного хеша;
- `LockService` против параллельных обработчиков;
- повторы только сетевых ошибок, HTTP 429 и 5xx;
- русские записи об ошибках;
- отсутствие любых изменений данных и оформления таблицы.

Добавить русское меню `Atlas`: «Установить синхронизацию», «Отправить все данные», «Проверить подключение», «Удалить триггеры Atlas». Управлять только собственными триггерами.

Пользовательскую инструкцию сохранить в `integrations/google-sheets/marketing-actual/ИНСТРУКЦИЯ.md`:

1. Подготовить публичный HTTPS-адрес Atlas; `localhost` недоступен Apps Script.
2. Открыть «Расширения → Apps Script» и вставить `Code.gs`.
3. Добавить Script Properties:
   - `ATLAS_ENDPOINT_URL`;
   - `ATLAS_WEBHOOK_SECRET`;
   - `ATLAS_SHEET_NAME`.
4. Запустить «Установить синхронизацию» и подтвердить разрешения.
5. Проверить подключение, выполнить первичную отправку и тестовую правку.

Таблицу не публиковать и не открывать сервисному аккаунту. Секрет хранить только в Script Properties.

## 8. Обновление интерфейса без перезагрузки

Добавить:

```text
GET /api/sync/marketing-actual
GET /api/updates/marketing-actual
```

Первый endpoint возвращает безопасные метаданные: время, число строк, максимальную дату, ревизию и краткую ошибку. Второй реализовать как Server-Sent Events с начальной ревизией, событиями изменения, heartbeat, `Cache-Control: no-store`, отключением proxy buffering и очисткой соединения.

В `DashboardApp` открыть один `EventSource`. При новой ревизии тихо загрузить маркетинг с текущими параметрами. Не вызывать `window.location.reload`, `router.refresh`, не менять localStorage и не показывать общий skeleton. Старые данные оставить до готовности целого ответа; устаревшие запросы отменять.

Убрать тексты о демонстрационном факте и фиксированном августе. `actualThrough` вычислять по максимальной принятой дате. Показывать время обновления факта.

## 9. Проверка

Тестами покрыть даты и русские числа, нули, формулы, дубликаты, HMAC, просроченный timestamp, повтор события, patch/очистку, части снимка, атомарность, гонку patch со снимком, дневную агрегацию, общий расчёт, динамический `actualThrough` и SSE без сброса фильтров.

На копии таблицы проверить первичную отправку, одиночную правку, вставку, очистку, удаление строки, изменение формулы, недоступность Atlas, неверный секрет, восстановление SSE и сохранение состояния интерфейса.

Обязательные команды:

```powershell
npm test
npm run lint
npm run build
docker compose up --build
```

## 10. Ограничения и границы

Edit-trigger не запускается для формул, других скриптов и Sheets API, поэтому минутная сверка обязательна. После установки проверить квоты и длительность Apps Script; при необходимости сделать интервал настраиваемым и увеличить до пяти минут.

В задачу не входят деплой и публичный домен, открытие таблицы, дневная группировка, изменение плана, замена демо-данных других вкладок, авторизация и роли.
