# Подключение маркетингового факта к Atlas

Таблицу не нужно публиковать, открывать по ссылке или предоставлять сервисному аккаунту. Установленный Apps Script сам читает разрешённый лист и отправляет в Atlas только восемь полей маркетингового факта.

## 1. Подготовьте Atlas

Atlas должен быть доступен по публичному HTTPS-адресу. Локальный адрес недоступен из Apps Script.

Создайте отдельный длинный случайный секрет и задайте на сервере переменные окружения:

    MARKETING_ACTUAL_WEBHOOK_SECRET=<случайный секрет>
    MARKETING_ACTUAL_SPREADSHEET_ID=<идентификатор закрытой таблицы из её URL>
    MARKETING_ACTUAL_SHEET_NAME=<точное название листа>

Секрет и рабочий адрес не добавляйте в Git. После изменения окружения перезапустите Atlas и примените миграции Prisma.

Первая строка листа должна содержать по одному столбцу с каждым заголовком:

1. Дата
2. Направление
3. Посещения
4. Лиды
5. Рекламный бюджет, ₽
6. Конверсия Лид/Посещение
7. CPC, ₽
8. CPL, ₽

Дополнительные столбцы допустимы: скрипт их не отправляет. Если несколько непустых строк описывают одно направление за одну дату 2026 года, перед отправкой скрипт суммирует посещения, лиды и бюджет, а производные показатели пересчитывает. Исходные строки таблицы не изменяются.

## 2. Добавьте Apps Script

1. Откройте закрытую таблицу.
2. Выберите «Расширения → Apps Script».
3. Замените содержимое Code.gs кодом из файла Code.gs этой папки.
4. Откройте «Настройки проекта → Свойства скрипта».
5. Добавьте:
   - ATLAS_ENDPOINT_URL — публичный HTTPS-адрес Atlas, например https://atlas.example.ru;
   - ATLAS_WEBHOOK_SECRET — тот же секрет, что задан на сервере;
   - ATLAS_SHEET_NAME — точное название листа.
6. Сохраните проект и обновите страницу таблицы.

Секрет должен храниться только в свойствах скрипта. Не вставляйте его непосредственно в Code.gs.

Вместо ручного заполнения свойств можно использовать одноразовый код подключения, подготовленный на компьютере с Atlas. Код содержит адрес, секрет и идентификаторы таблицы и листа в Base64URL-формате, вставляется только в диалог «Настройка Atlas» и сохраняется в свойствах скрипта. Код подключения, `.clasp.json` и OAuth-данные не коммитятся в Git.

## 3. Установите синхронизацию

1. В таблице откройте меню «Atlas».
2. Нажмите «Установить синхронизацию».
3. Если свойства ещё не заданы, вставьте одноразовый код подключения и нажмите «ОК».
4. Подтвердите разрешения Google для чтения таблицы, управления триггерами и HTTPS-запросов.
5. Дождитесь сообщения об успешной отправке первичного снимка.
6. Выберите «Atlas → Проверить подключение».

Скрипт создаёт только собственные триггеры:

- edit-trigger немедленно отправляет полный агрегированный снимок после изменения или очистки строки;
- change-trigger отправляет полный снимок после вставки, удаления или перестановки строк и столбцов;
- минутный trigger сверяет SHA-256 и покрывает изменения формулами, импортами, Sheets API и другими скриптами.

Одновременно выполняется только один обработчик Atlas. Сетевые ошибки, HTTP 429 и ошибки сервера 5xx повторяются автоматически; ошибки данных не повторяются.

## 4. Проверьте работу

На копии таблицы последовательно проверьте:

1. первичную отправку всех данных;
2. правку одной строки;
3. очистку заполненной строки;
4. вставку и удаление строки;
5. изменение формулы;
6. временную недоступность Atlas и последующее восстановление;
7. неверный секрет;
8. обновление открытого дашборда без перезагрузки и без сброса фильтров.

В Atlas должны обновляться время синхронизации, число строк, максимальная дата факта и ревизия. При ошибке полный снимок применяется транзакционно: предыдущий успешный набор данных остаётся доступным.

## 5. Локальная проверка на Windows

Этот сценарий предназначен только для временной проверки локального Atlas. Для постоянной работы нужен стабильный HTTPS-адрес сервера.

1. Запустите Atlas из корня проекта:

       docker compose up --build

   Если установлен старый отдельный Compose, используйте `docker-compose up --build`.
2. Убедитесь, что Atlas отвечает по адресу `http://127.0.0.1:3000/api/health`. Ожидаемый ответ — HTTP 200 и `{"status":"ok"}`.
3. Откройте временный HTTPS-туннель. В Windows указывайте `127.0.0.1`, а не `localhost`:

       ssh -p 443 -R0:127.0.0.1:3000 -t free.pinggy.io x:https

   Не закрывайте это окно SSH до окончания проверки. Если анонимный вход закрывается на запросе пароля, создайте одноразовый ключ во временной папке и явно передайте его:

       ssh-keygen -t ed25519 -f "$env:TEMP\atlas-pinggy-ed25519"
       ssh -p 443 -i "$env:TEMP\atlas-pinggy-ed25519" -o IdentitiesOnly=yes -o ServerAliveInterval=30 -R0:127.0.0.1:3000 -t free.pinggy.io x:https

4. Скопируйте выданный туннелем адрес `https://…` и проверьте `<адрес>/api/health`. Для Pinggy передавайте заголовок `X-Pinggy-No-Screen: 1`; Apps Script уже добавляет его к запросам.
5. Подготовьте новый одноразовый код подключения. Значения секрета и идентификатора таблицы берутся из локального `.env`, идентификатор листа — это число `gid` из адреса открытого листа:

       $endpoint = "https://адрес-временного-туннеля"
       $sheetId = 123456789
       $settings = @{}
       Get-Content -LiteralPath ".env" -Encoding UTF8 | ForEach-Object {
         if ($_ -match '^\s*([^#][^=]*)=(.*)$') {
           $settings[$matches[1].Trim()] = $matches[2].Trim()
         }
       }
       $payload = [ordered]@{
         endpoint = $endpoint
         secret = $settings["MARKETING_ACTUAL_WEBHOOK_SECRET"]
         spreadsheetId = $settings["MARKETING_ACTUAL_SPREADSHEET_ID"]
         sheetId = $sheetId
       }
       $json = $payload | ConvertTo-Json -Compress
       $token = [Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes($json)).TrimEnd("=").Replace("+", "-").Replace("/", "_")
       Set-Clipboard -Value $token

   Не выводите код в терминал и не сохраняйте его в Git: он содержит webhook-секрет.
6. В таблице выберите «Atlas → Настроить подключение», вставьте код из буфера и нажмите «ОК».
7. При первой настройке выберите «Atlas → Установить синхронизацию». При смене только адреса туннеля повторно устанавливать триггеры не нужно.
8. Для немедленной проверки выберите «Atlas → Отправить все данные». После успешного ответа измените одну цифру на разрешённом листе и не обновляйте страницу дашборда: изменение должно появиться автоматически.

Бесплатный временный адрес Pinggy действует ограниченное время и меняется после перезапуска туннеля. Он открывает локальный дашборд в интернете любому, кто знает случайный адрес, поэтому такой способ нельзя использовать как постоянное размещение. Webhook дополнительно защищён HMAC-подписью, но сам дашборд этим секретом не закрыт.

## 6. Диагностика

### В дашборде одни прочерки

1. Выберите «Atlas → Отправить все данные».
2. Проверьте `http://127.0.0.1:3000/api/sync/marketing-actual`.
3. Убедитесь, что в ответе есть успешное время синхронизации, ненулевое число строк и отсутствует ошибка.
4. Проверьте выбранные в дашборде период и направление: данные вне активных фильтров не отображаются.

### «Таблица или лист не входят в список разрешённых»

Значения `MARKETING_ACTUAL_SPREADSHEET_ID` и `MARKETING_ACTUAL_SHEET_NAME` в окружении Atlas не совпадают с фактической таблицей или точным названием листа. Исправьте `.env`, затем пересоберите или перезапустите Atlas. После этого повторите «Отправить все данные».

### Полная отправка работала, но новая цифра не появляется

Сначала откройте `<публичный адрес>/api/health`. Если адрес не отвечает, временный туннель завершился. Запустите новый туннель, создайте код с новым адресом и выполните только «Atlas → Настроить подключение». Затем нажмите «Проверить подключение» или «Отправить все данные».

Если публичный адрес отвечает, сравните поле `revision` в `/api/sync/marketing-actual` до и после изменения:

- ревизия увеличилась — Atlas получил данные; проверяйте соединение открытого дашборда с `/api/updates/marketing-actual` и активные фильтры;
- ревизия не изменилась — откройте «Atlas → Проверить подключение», затем журнал выполнений Apps Script и найдите ошибку обработчика `atlasOnEdit` или `atlasMinuteCheck`.

Минутный триггер страхует обычный edit-trigger, поэтому после временной сетевой ошибки изменение должно быть отправлено при следующей проверке. Команда «Отправить все данные» выполняет ту же отправку немедленно.

## 7. Проверенный результат

Локальная схема проверена на закрытой Google Таблице: первичный полный снимок загрузился, после смены истёкшего адреса туннеля повторная настройка подключения восстановила отправку, а изменение цифры появилось в открытом дашборде. Публиковать таблицу или выдавать к ней общий доступ для этого не требуется.

## 8. Отключение

Выберите «Atlas → Удалить триггеры Atlas». Команда удаляет только триггеры, созданные этим скриптом, и не меняет данные или оформление таблицы.
